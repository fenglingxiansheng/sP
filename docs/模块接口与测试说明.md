# 模块接口与后续测试入口

本项目没有 HTTP 后端接口。下表中的接口都是可导入的 JavaScript 模块；核心模块不依赖 Vue，可直接用 Node.js 测试。DOM 和文件下载能力需在浏览器中测试。

## 模块位置

| 文件 | 主要接口 | 输入与返回 |
| --- | --- | --- |
| `src/core/color.js` | `rgbToLab(rgb)` | `[r,g,b]` → D65 Lab 三元组 |
| 同上 | `createMatcher(palette)` | 返回颜色匹配函数：RGB → 色号；CIE76，同距按色表顺序选第一项 |
| `src/core/pattern.js` | `gridSize(sourceWidth,sourceHeight,width)` | 原图尺寸和目标宽度 → `{width,height}`；非法或超限抛错 |
| 同上 | `sampleGrid(image,width,crop=null,options={})` | `{width,height,data:RGBA}` → `{width,height,colors}`；颜色为 RGB 或 null；crop 指定原图像素区域，只在该区域内采样 |
| 同上 | `matchGrid(grid,palette)` | 采样网格 → Pattern，格子保存品牌色号 |
| 同上 | `countBeads(pattern)` | Pattern → `{total,colors,items:[{code,count}]}`；不计空格 |
| `src/core/editor.js` | `lineCells(from,to,width,height)` | 整数坐标 → 连续线段的格子索引，避免快速拖动漏格 |
| 同上 | `createEditor(pattern)` | 返回编辑器，见下文的事务约定 |
| `src/core/image.js` | `imageHeader(arrayBuffer)` | PNG/JPEG 文件头 → 尺寸；未知格式抛错 |
| 同上 | `decodeImage(file)` | Promise → RGBA 像素数据；校验文件大小和解码像素预算 |
| `src/core/project.js` | `serializeProject(name,pattern,palette)` | 校验并返回带版本号的 JSON 文本 |
| 同上 | `parseProject(text)` | 校验后返回 `{schemaVersion,name,pattern,palette}`；无效输入抛错 |
| `src/core/render.js` | `drawPreview(canvas,pattern,palette,options)` | 绘制编辑预览；options 包含 cell、labels、grid |
| 同上 | `renderSheet(pattern,palette,name)` | 返回整幅 PNG 图纸对应的 Canvas，固定每格 32 px |
| 同上 | `exportPng(pattern,palette,name)` | Promise → PNG Blob，不依赖当前屏幕和缩放 |
| 同上 | `downloadBlob(blob,filename)` | 发起浏览器下载，并回收临时对象 URL |
| `src/composables/useStudio.js` | `useStudio()` | Vue 页面状态及上传、生成、编辑、保存等操作 |
| `src/components/PixelCanvas.vue` | props / events | 接收图案与视图参数；发出 start、move、end、hover 格子事件 |

## 数据约定

Pattern：`width`、`height`、`cells`、`paletteId`、`paletteVersion`、`settings`。

- `cells` 按行优先存储，索引为 `y * width + x`；每格是色号字符串或 null。
- 宽高为 1～128 整数，格子数量严格等于宽乘高。
- `settings` 包含 width、sampling=`nearest` / `smooth` / `edge`、transparency=`empty-or-white`、matching=`lab-cie76`。
- 色表颜色为 `{code,rgb,hex}`，RGB 为 0～255 整数，hex 从 RGB 推导。
- 上传和项目文件上限为 10×1024×1024 字节；原图解码前限制为 1600 万像素。
- JSON schemaVersion 当前为 1。未知版本、重复色号、未知格子色号、超限尺寸、版本不一致均拒绝载入。

## 编辑器事务

1. `begin()` 开始一次用户操作。
2. `paint(indices,code)` 更新格子，传 null 表示擦除；或 `replace(from,to)` 全局替色。
3. `commit()` 完成一次操作，返回是否发生实质修改。无变化不加入历史。
4. `undo()` / `redo()` 切换图案；通过 `pattern`、`canUndo`、`canRedo` 获取状态。

调用方保证编辑使用当前色表的色号，并在 begin/commit 之间执行修改。一次拖动可以多次 paint，但只 commit 一次。新编辑会清空重做。历史仅在内存中，不写入项目文件。

## 矩形裁剪补充

- `src/core/crop.js`：`validateCrop(image,crop)` 校验原图内的非空整数矩形；`cropFromPoints(a,b,image)` 支持正向或反向框选、边界限制与最小一像素。
- `ImageCropper.vue`：输入 source、url、crop，发出 apply 或 close；草稿仅在确认后生效，取消不会改变已确认范围。
- `useStudio` 提供 crop、cropOpen、applyCrop；选区变化标记为待生成，不直接覆盖编辑成果。
- `settings.crop` 是可选字段，包含 x、y、width、height、sourceWidth、sourceHeight；坐标为解码后原图像素。保存时验证区域边界与生成比例，不保存原图。
- 旧 schemaVersion=1 文件仍兼容。新裁剪项目可在当前版本载入和编辑，重新裁剪仍需上传原图。
- 新增 3 组测试，合计 12 组：裁剪区域采样排除背景、反向框选与边界、项目参数恢复与非法数据拒绝。

## 尺寸与像素化接口

- `sizing.js`：`boardCapacity(count)` 接受 1、4、9，返回方形宽高上限；`fitGrid(sourceWidth,sourceHeight,maxWidth,maxHeight)` 返回等比例放入范围内的整数格数。
- `sampleGrid` 的 options 支持 `height`（高度上限）、`style`、`mask`（与原图等大的 Uint8Array）、`backgroundRemoved`。未提供 height 的旧调用仍沿用原宽度驱动规则。
- `pixelate.js`：`visibleColor` 处理白底合成与蒙版；`areaColor` 执行面积权重平均或主色分组。主色分组每个 RGB 通道使用 32 级间隔；相同权重按首次出现顺序取组。
- 平滑/主色采样不把透明或擦除像素当作白色混入；可见覆盖不足半格时留空。半透明可见像素仍先按白底合成。
- 项目 `settings.bounds={width,height}`、`backgroundRemoved:boolean` 均可选，crop 不变；解析校验上限、风格和裁剪适配结果，兼容旧文件。

## 背景处理接口

- `background.js`：`createMask(image)` 创建全 0 Uint8Array。0 表示保留原始 alpha，1 表示擦除。
- `paintMask(mask,image,from,to,radius,restore=false)` 原地更新蒙版，连线为圆头连续笔刷，返回是否改变；restore 恢复原始透明度，不修改 source.data。
- `cornerSeeds(image,tolerance)` 从非透明四角选取最接近的一组颜色；全透明四角返回空列表。
- `removeConnectedColor(image,mask,seedIndices,tolerance)` 以每个固定种子 RGB 为参照执行四连通搜索，原地更新 mask，返回是否改变；容差 0～100。不会沿渐变不断漂移匹配标准。
- `maskCount(mask,image)` 只统计原图可见且被擦除的像素。
- `BackgroundEditor.vue` 接收 source 和可选 mask，应用时发出 `{mask,count}`；取消不更改父状态。内部历史独立于拼豆格子编辑历史。
- 背景编辑针对完整原图；生成时在裁剪区域内应用相同坐标系的蒙版，随后进行像素化与色号匹配。
- 背景蒙版及原图不写进项目 JSON；生成后的空格已保留去背景效果。

新增 7 组检查，总计 19 组；浏览器覆盖尺寸预设、滑块、各风格、纯色去除、内部同色保护、擦除恢复、取消、项目往返及窄屏。后续重点测试同色相连误删、照片渐变背景、非常细小主体、16 MP 大图、边缘笔刷、后台标签页恢复和跨浏览器性能。

## 自动主体抠图增量接口

`createSubjectRemover()` 提供 `run(source, progress): Promise<Uint8Array>`、`cancel()`。每个背景窗口持有一个 Worker；source 复制到 Worker，不转移或修改原图。Worker 内加载固定 U2NetP，预处理、推理和蒙版放大；`subjectMask` 负责阈值转换和无效输出拒绝。成功后整体替换窗口蒙版并提交一步历史，失败/取消不提交。卸载终止 Worker。

验收：首次一键抠图→检查预览→笔刷擦除/恢复→撤销/重做→应用并生成；重复自动识别取消确认或取消运行都应保留旧蒙版；模型404应显示失败且手动工具可用；断网时本机资源仍能运行。模型与浏览器缓存不进入项目 JSON。


## 2026-10-13 Anime Segmentation 增量

默认 Worker 切换 ISNet 1024输入。`animeRegion` 计算等比居中补边；`subjectMask` 新增 region/normalize 选项，动漫概率使用 normalize:false，防止把低置信度噪声强制拉为前景。补充横竖图去补边与绝对概率阈值测试。

实际验证：23 项 Node 测试通过；生产构建通过。Chrome 对上游 banner 中一张原图区域进行真实推理：开发版约 8.3 秒，生产版约 10.5 秒（包含首次本地加载和初始化，单机单样例，不是性能承诺）。人物主体可见、背景被移除；两版均验证撤销、重做和取消。模拟模型 404 后显示错误，手动工具仍可用。官方权重 SHA256 与本地文件一致，`npm run model:download` 已验证本地命中校验。尚未以用户失败图片进行质量对比。

## 点选保留与原图参考

新增共用 `ImageViewport.vue`：裁剪与背景处理窗口使用同一套 Ctrl＋滚轮锚点缩放、Space＋左键平移、适应窗口复位。视图变换不进入编辑历史。捕获阶段拦截平移手势，输入控件不拦截空格，失焦清除按键状态，卸载清理监听；编辑拖动期间阻止缩放。浏览器已验证两个窗口锚点位置、平移距离、视图操作不改变数据/历史、松开空格后裁剪和笔刷恢复、复位。

`restoreConnectedColor(image, mask, seeds, tolerance)` 按源图种子固定颜色进行连通恢复，设置蒙版为0，不修改源图RGBA。与背景去除共享遍历，支持一步撤销。参考层只是预览，不改变 maskCount 或导出。24 项单元测试、构建通过；真实 saber 原图复现左右袖子误删，在点选种子处恢复后，两处蒙版从1变0，抽查背景点仍为1。这只是点级回归，不代表袖子完整分割。浏览器验证点选、参考开关、撤销/重做；高容差会恢复相似背景，需要继续笔刷修整。
